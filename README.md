# Сканер линейных неэффективностей рынка

Фоновая программа. Каждую минуту она получает цены по всему рынку, сама ищет закономерности, проверяет их на новых данных и выдаёт сигналы для торговли на Bybit. Все минутные свечи сохраняются у вас на компьютере для будущих бэктестов.

## Программа с окном (MarketScanner.exe)

Удобнее всего пользоваться сканером через программу с окном. Как получить `.exe`, описано в `BUILD_EXE.md`. Из исходников окно запускается командой `python app.py`.

Вкладки:
- **Сигналы** — лента новых сигналов: что купить или продать, на сколько минут, ожидание, издержки, причина. Двойной щелчок по строке показывает подробности.
- **Закономерности** — активные и проверяемые закономерности с результатами.
- **Отчёты** — отчёт за сутки, неделю или месяц одной кнопкой.
- **База истории** — загрузка глубокой истории, выгрузка в CSV, бэктест по базе.
- **Журнал** — ход работы и ошибки.
- **Настройки** — ключи Финама и Alpaca, тикеры Мосбиржи, комиссии Bybit, автозапуск вместе с Windows, сворачивание в трей, уведомления о сигналах.

Программу можно запустить только в одном экземпляре. Крестик сворачивает её в трей возле часов, и сканер продолжает работать. Чтобы выйти совсем, нажмите на значок в трее → **Выход**.

Дальше описана работа из консоли. Окно делает всё то же самое.

## Площадки

| Префикс | Площадка | Роль | Нужен ключ |
|---|---|---|---|
| `YS:` | Bybit спот: крипта и токенизированные акции xStocks | **торгуем** | нет |
| `YF:` | Bybit перпы: крипта и акции | **торгуем** | нет |
| `S:`, `F:` | Binance спот и перпы (в т.ч. на акции) | источник «кто опережает» | нет |
| `FN:` | Мосбиржа через брокера Финам | источник | ключ Finam Trade API |
| `A:` | акции США через Alpaca | источник | бесплатный ключ |

Сигналы выдаются только по инструментам Bybit (`trade_prefixes` в `config.json`). Остальные площадки используются как подсказки: например, «перп NVDA на Binance опережает токен NVDAX на Bybit» или «фьючерс на Мосбирже опережает BTCUSDT на Bybit».

Для сканера ключи от Bybit и Binance не нужны: он берёт только публичные котировки. Ключ Bybit понадобится позже, для автоторговли.

## Установка

```
pip install numpy pandas
pip install tzdata          # только на Windows
python market_scanner.py init-config
```

## Подключение Мосбиржи через Финам

1. Получите ключ (secret) в личном кабинете Финама, в разделе Trade API.
2. Найдите точные тикеры:
   ```
   python market_scanner.py finam-search BTC
   python market_scanner.py finam-search Si
   ```
3. Впишите ключ и тикеры в `config.json` (формат `ТИКЕР@MIC`):
   ```json
   "finam": {"enabled": true, "secret": "ВАШ_КЛЮЧ", "symbols": ["SBER@MISX", "SiZ6@RTSX"]}
   ```

Фьючерсы истекают раз в квартал, поэтому в день экспирации замените тикер на следующий контракт.

Часы работы Мосбиржи сканер определяет по фактическим сделкам, так что вечерние сессии и сессии выходного дня учитываются сами.

## Подключение акций США (Alpaca)

Зарегистрируйтесь на https://alpaca.markets (подойдёт и учебный paper-счёт), создайте API-ключ и впишите его:

```json
"alpaca": {"enabled": true, "key_id": "…", "secret_key": "…", "feed": "iex", "max_symbols": 60}
```

Без Alpaca сканер всё равно работает с перпами и токенами на акции.

## Запуск

```
python market_scanner.py live      # работа в реальном времени
python market_scanner.py status    # активные закономерности и последние сигналы
```

- **Windows (в фоне):** `pythonw market_scanner.py live`. Для автозапуска добавьте эту команду в Планировщик заданий.
- **Linux / VPS:** `nohup python3 market_scanner.py live > /dev/null 2>&1 &`

Сканер можно перезапускать в любой момент. Обученные закономерности сохраняются, а история после перерыва догружается сама, только недостающие минуты.

## База истории для бэктестов

Все минутные свечи (open, high, low, close, volume) по всем инструментам пишутся в `scanner_data/history.db` (SQLite). Сохраняются только минуты, в которые были сделки.

```
python market_scanner.py backfill --days 90     # скачать историю за 90 дней по всем инструментам
python market_scanner.py db-info                # сколько данных, за какой период, размер
python market_scanner.py export --out data --from 2026-11-01 --to 2026-11-15 --symbols YF:BTCUSDT,F:BTCUSDT
python market_scanner.py replay --from-db --from 2026-11-01    # прогнать сканер по базе
```

- `backfill` можно запускать повторно: он докачивает только то, чего ещё нет. Финам и Alpaca могут ограничивать глубину минутной истории, а у Binance и Bybit она многолетняя.
- `export` создаёт CSV на каждый инструмент. Колонки: время (UTC), open, high, low, close, volume. Файлы открываются в Excel, Python, TradingView и т. п.
- `replay` пишет результаты в отдельную папку `scanner_data_replay` и не трогает память живого сканера.
- **Объём:** около 250 инструментов дают примерно 5 ГБ за год непрерывной работы.

Базу можно открыть любым просмотрщиком SQLite, например DB Browser for SQLite. Таблицы: `symbols(id, name)` и `bars(sid, ts, o, h, l, c, v)`, где `ts` — время в миллисекундах UTC.

## Ежедневный отчёт для анализа

Каждый день в полночь (по `display_utc_offset`) сканер сам сохраняет диагностический отчёт за прошедшие сутки в `scanner_data/reports/report_ГГГГ-ММ-ДД.md` и такой же `.json`. Отчёт только читает данные и ничего не меняет.

Его можно построить и вручную, за любой период:
```
python market_scanner.py report                 # последние сутки
python market_scanner.py report --days 7        # неделя
python market_scanner.py report --from 2026-11-01 --to 2026-11-15
```

Что в отчёте:
1. итог по сигналам после издержек и какую долю валовой прибыли съели издержки;
2. ожидание против факта: окупаются ли слабые сигналы, честна ли модель;
3. разрезы по типу закономерности, горизонту, площадке, часу суток, инструментам;
4. переобучение: насколько живой результат хуже того, что было при отборе, и как закономерности стареют;
5. жизненный цикл, включая «мигающие» гипотезы;
6. работа поиска;
7. здоровье данных: пропуски, ошибки сети, неликвидные инструменты;
8. текущие параметры;
9. автоматические наблюдения.

Каждая бумажная сделка с ожиданием, фактом и издержками лежит в таблице `trades` в `scanner.db`.

## Что где лежит (`scanner_data/`)

| Файл | Что внутри |
|---|---|
| `history.db` | история свечей |
| `signals.jsonl` | сигналы, по одному JSON на строку |
| `scanner.db` | сигналы, события (найдена / активирована / списана), текущие гипотезы |
| `scanner.log` | журнал |
| `state.pkl` | память модели |
| `reports/` | ежедневные отчёты |

## Как устроен поиск

1. Круглосуточные инструменты сравниваются по всем минутам. Ищутся автокорреляция, опережение (lead-lag), отклонение от рынка и коинтеграция пар.
2. Связи с акциями США ищутся только по минутам сессии NYSE, связи с Мосбиржей — только по минутам, когда она торговала.
3. Связь должна быть сильной на первых 70% окна и давать прибыль после комиссий Bybit на последних 30%.
4. Двойники убираются: на один инструмент остаются только причины, которые дают новую информацию.
5. Каждая связь торгует на бумаге со своей мини-моделью, которая дообучается каждую минуту. Сигналы выдаются, только когда связь доказала себя на новых данных.
6. Если по инструменту больше 3 минут не было сделок, по нему не торгуем.

## Главные настройки

| Параметр | Смысл |
|---|---|
| `cost_per_side` | комиссия на сторону. Bybit VIP0: спот 0,1%, перпы 0,055% (тейкер). Если у вас VIP-уровень или вы торгуете лимитками, поставьте свои значения. |
| `trade_prefixes` | по каким площадкам выдавать сигналы |
| `bybit_spot.top_n`, `bybit_linear.top_n` | сколько инструментов Bybit сканировать |
| `window` | сколько минут истории используется в поиске (6000 ≈ 4 суток) |

## Ограничения

- Подключения к биржам проверены на имитации их API, а не на реальных серверах. При первом запуске посмотрите в `scanner.log` строку `Источники: …` и сообщения об ошибках.
- Это исследовательский инструмент. Прибыль на бумаге не гарантирует прибыль в реальной торговле.
